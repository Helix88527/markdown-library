# 项目位置与 Markdown 归档

先用 locate_database.py 定位配置，plan_output.py 只读规划。用户指定输出位置优先；未指定时在源文件或输入目录处理，资料库位置不改变原项目位置。库外材料也不为适配媒体管理器自动搬动。

默认布局：
```text
Markdown/
  <标题>.md
原始资料/…/<原项目>/
  原始材料
  参考资料/
  图片及处理记录
```

当用户要求建立或更新资料库时，沿用该任务要求：保留项目原稿，将最终 Markdown 平铺到配置的目录；**不为每篇新建目录，不重复复制附件或参考资料**。成稿中的链接可指向原始资料对应位置，例如：
```markdown
[参考目录](<../原始资料/文字资料/某篇文章/参考资料/参考资料目录.md>)
```

```text
<Python> scripts/safe_copy_to_cooked.py <最终.md> --database-root <根目录> --confirmed-by-user --json
```

脚本将正文中的本地链接按成稿入口重定位，保留锚点及远程链接，代码示例不改；沿 Markdown 参考目录检查实际文件存在。引用文件留在源处，因此源项目应作为资料库的一部分保留。库外项目保留原位置，跨盘时需要可解析的绝对本地链接，不静默复制原件。

只有链接位置变化时，源稿与成稿稿的字节哈希可以不同；校验应比较预期重定位结果，并检查实际依赖，不能以两份哈希必须相等误报。媒体临时目录的依赖必须先存入永久位置再归档，不能完成后清理掉正在引用的证据。

同名同内容复用；不同内容拒绝覆盖，以保护人工稿。比较后用 --archive-name <新文件名或stem> 保存修订。Word 仅在用户明确要求或实际纳入成果时归档。旧 bundle-1 目录继续支持读取和校验，不批量搬迁旧成果；只有用户要求调整的项目按新布局迁移。
