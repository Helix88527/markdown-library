# 现成文字与文章流程

用户直接要求处理文字，默认是把已有内容整理进 Markdown，核实说法并补充背景。原文措辞通常可直接保留，不把任务转成逐字校对或文字质量审计；不询问媒体阶段模式。

HTML、MHTML、TXT、MD、DOCX 和有文本层 PDF 可用 extract_article.py 提取，扫描件才需要 OCR。X HTML 自动转入专门分支。
```text
<Python> scripts/extract_article.py <明确来源或目录> --json
```

默认每个原件旁生成 <stem>_处理结果/00_资料信息.json 与 01_原始正文.md。跳过参考目录及既有结果；来源相同且哈希一致复用，冲突不覆盖。检查提取是否取到完整主正文、是否混入导航／推荐文章、顺序和归属是否正确。这个边界检查不能扩张成正常文字逐句找错。

明确区分原作者、当前发布者、转载导语或按语。无证据不猜作者；转载不等于完全认同。原有图片可提取候选，是否采用需看图；正文外头像和推荐卡不算文章插图，替代文字不当作 OCR。

成稿保留内容、论证、具体例子与限定条件，用标题、段落和列表改善阅读。可以保留原文全文后单列分析，也可在保全有效信息和归属的前提下组织正文。只删除页面噪声和无信息重复，不缩成替代全文的短摘要。

随后按 article-record-template.md 补充主题分析、必要背景、重要说法核验及参考目录。仅出现乱码、漏字、OCR／提取错误或用户要求校对时，才作有依据的文字修正并简要说明。原作者实际说错的事实在核验层解释，不伪装成笔误改写；普通排版不必列校正表。

可直接生成最终稿；若长文需要分开组装，可保存 02_整理正文.md，或将已干净的 01 直接传入 assemble_record.py，metadata 使用 text_organization 模式。普通文字不强制 01→02 校订、逐段覆盖报告或专门的文字审校关卡。检查内容有无遗漏与链接能否打开即可，主要工作应落在内容理解和证据上。

参考资料留在源项目。最终 Markdown 平铺到Markdown根目录，链接回原始资料或原项目；见 output-location-and-ingestion.md。原件保留。
