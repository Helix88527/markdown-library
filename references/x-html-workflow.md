# 推特 HTML 流程

推特页面按卡片提取，不当作一篇连续文章。仅保存外壳时报告需要补充已展开页面，不输出空成功。

```text
<Python> scripts/extract_x_html.py <HTML> --json
```

extract_article.py 也识别常见卡片或 X 页面元数据并自动转入。输出 <stem>_处理结果/00_资料信息.json 和 01_原始正文.md。

每条保留页面顺序、可靠 ID、账号、时间、永久链接、正文、图片、引用与回复关系。用卡片时间链接确定身份，不用正文随意提到的帖子链接猜 ID。引用卡片单独记录作者与文字，转推提示保留，不推断完全认同。回复有明确父帖 ID 才登记，缺上文提示，不编造线程。完全相同卡片去重，同 ID 不同内容保留并告警。

页面可能有其他账号回复，每条分别归因。保存 DOM 不证明完整线程或账号全部发言。缺失 ID、折叠正文、未展开回复和版本冲突需记录；需要时联网补充并登记来源。

支持常见 data-testid=tweet 卡片、嵌套引用和 role=link 引用卡片。平台 DOM 变化时应检查输出，不能凭成功退出宣称完整。原有本地或 data 图片保存为候选；远程、blob、缺失或不支持格式如实标记，替代文字不是 OCR。

现成推文按文字整理处理，不默认逐字校订或校正表。保留各帖归属，可加线程标题但不猜关系；可直接成稿，需要分开组装时才另存 02_整理正文.md。用 x-record-template.md 和统一组装流程；核验定位到 ID／链接，缺失时用页面顺序。事实核验与原文分层，采用资料登记到参考目录。
