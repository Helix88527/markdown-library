# 内容完整性与媒体全文校验

现成文字默认核对提取范围和内容是否遗漏，重点是整理、背景和说法核验。不要求为正常原文逐段做文字校订，不强制创建 02、校订表或覆盖报告。仅有 OCR／提取异常或用户要求校对时按需要核对。原文的事实问题在核验部分说明。

媒体转写仍要逐段核对 01→02，保留有效信息并记录重要识别修正。assemble_record.py 将当前 02 原样纳入源侧成稿，生成 fulltext-1 报告；audit_source_fidelity.py 核对当前 02 哈希、全文标记、嵌入文本和必需章节。哈希不能证明识别正确或事实真实。

```text
<Python> scripts/assemble_record.py <02> <最终.md> --analysis <分析.md> --metadata <头.json> --report <覆盖.json>
<Python> scripts/audit_source_fidelity.py audit <02> <最终.md> <覆盖.json> --json
```

普通文字可选择借用组装器，text_organization 模式使用正文整理标题并省去校正章节要求；机械复制检查不等于重新要求文字审校。

旧逐项报告继续按既有规则审核，不凭升级跳过旧媒体任务的暂停或完整性要求。当前稿件变化后重新组装，不手改哈希绕过检查。

最终 Markdown 平铺归档时，只为本地引用重定位路径，源侧全文报告仍针对原路径成稿；成稿副本由归档校验器比较重定位后的预期文本并检查依赖。不能直接拿源稿哈希要求路径已改变的成稿稿相同。
